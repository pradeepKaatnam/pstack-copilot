Packaging and safety
--------------------
Install only copilot/, whose legacy plugin.json explicitly selects skills/ and
agents/. The complete archive is outside that package. No active package points
its discovery paths into upstream/. Archived nested Benny skills and Cursor
agents/manifests are not installed. JSON compatibility notes are sidecars, never
illegal comments. Removed prompt blocks live in the archive/audit rather than
being hidden in active HTML comments. Comments are not a security boundary.
Portable scripts are resources, not automatic startup hooks.

Unsupported versus unverified versus deliberately not enabled
------------------------------------------------------------
Unsupported means the exact Cursor syntax/assumption has no verified mapping
in this package, not that Copilot can never offer the underlying capability.
Unverified means evidence or a host execution test is missing: do not invent
equivalence, enable an integration, or infer non-support from missing docs.
Documented native model, delegation, background, plugin and hook facilities
exist; choosing safe sequential/inherited behavior is a port policy, not a claim
that those facilities are absent. Missing MCP/tools stop the affected operation.
This port does not use hooks or HTML comments as immutable policy enforcement.

Validation boundaries
---------------------
Mechanical checks validate archive identity, complete mapping and exact passage
evidence, resources and discovery boundaries. Unit tests exercise preservation
and safe installation/update logic. Runtime test results are recorded separately
in validation.txt. No Copilot executable is installed in this sandbox, so actual
CLI discovery, manual-only invocation behavior, VS Code interaction, cloud
execution, permissions and optional MCP integrations have NOT been smoke-tested.
The documented install/list/invoke instructions are a user-run acceptance check,
not a fabricated successful integration test. No automatic merge is performed.

Official-documentation discrepancies observed
--------------------------------------------
The plugin overview and current CLI reference disagree about which marketplaces
are defaults; direct installation avoids depending on that distinction.
Cloud plugin settings are documented, while hook documentation describes a
different cloud settings loader: cloud plugin-hook loading remains unverified.
Generic agent docs retire infer while CLI-specific docs still list it; this port
does not depend on infer. CLI and VS Code differ in namespaces and direct-install
toggle behavior. Verify the actual chosen host interface rather than blending
these documents into a claim of feature parity.
